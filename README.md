# asset-manager（統合資産管理システム）

タグ・マスタ定義・カスタムフィールドに対応した、ブラウザ完結型の資産管理システムです。
資産データと画像の実体は、いずれもブラウザの IndexedDB（Dexie.js）に自動保存され、
サーバーは不要です。バックアップは画像を含めてZIPで持ち出せます。

## 起動方法

ビルドは不要です。いずれかの方法で開いてください。

```bash
# 方法1: そのままブラウザで開く
open index.html

# 方法2: ローカルサーバーで配信（推奨）
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

## 主な機能

- **ダッシュボード** — 6つのKPIを1行に集約。「要対応」を 停止中 / 期限超過 / 14日以内 に分け、各上位3件を表示（残りは「すべて表示」）
- **資産一覧** — リスト / カード / カレンダーの3ビュー。行頭の色ドットで状態、「次回予定」列で期限の近さ（超過=赤 / 7日以内=琥珀）を表示。
  狭い画面ではリストが自動でカード行に変わる
- **フィルタバー** — 稼働状況（色付きセグメント）とマスタごとのタグ条件を組み合わせて絞り込み。
  タグはドロップダウン内のツリー（件数・検索・よく使う）から選ぶ
- **資産詳細** — 4タブ（基本情報＋構成 / 画像 / 計画・履歴 / 運用・安全）。見出し下の概要チップで
  次回予定・最終実施・期限項目・画像・構成をタブを開かずに確認できる
- **マスタ管理** — マスタを上部タブで切り替え、タグ階層をツリー行（資産数・固有項目数つき、検索・折りたたみ可）で編集。グラフビューも利用可
- **資産構成** — 資産同士の親子関係をグラフで編集
- **横断検索（コマンドパレット）** — `Ctrl+K` で資産・タグ・操作を1つの入口から呼び出し
- **入力サジェスト** — 使用実績を学習し、タグ候補・実施内容・周期などを使いそうな順に提案
- **表示密度の切り替え** — コンパクト / ゆったり（⋮メニュー → 表示）
- **バックアップ** — データと画像をまとめてZIPで書き出し / 復元（画面へのドラッグ&ドロップにも対応）

### 入力を省く仕組み

同じ値を何度も選ぶ作業を減らすため、選ばれた回数と直近の使用時刻を学習し（半減期30日）、
並び順と提案に反映します。学習結果は並び順にしか使わず、候補自体は隠しません。

| 場面 | 提案されること |
| --- | --- |
| タグを選ぶ | 使用実績順に並び替え、上位4件はチップでワンクリック追加。`↑` `↓` + `Enter` でも確定 |
| 絞り込む | マスタのドロップダウン上部に「よく使う」タグを自動生成。件数は他の条件を反映して表示 |
| 新規登録する | 絞り込み中の分類を自動で引き継ぎ、「前回と同じタグを適用」も提示 |
| 名前を入力する | 重複の警告と、連番の候補（`AGV-01` → `AGV-02`） |
| 履歴・周期計画を入力する | 過去の実施内容を候補表示。周期は 30 / 90 / 180日 / 1年のプリセット付きで、次回予定日を自動計算 |
| 何かを探す | コマンドパレットが「最近開いた資産」「よく使う操作」順に並ぶ |

### 作業を短縮する導線

- **周期計画の「実施済み」** — 履歴への記録と次回予定の更新を1クリックで完了（「元に戻す」付き）。
  ダッシュボードの「要対応」からも直接実行できます
- **資産詳細の前後移動** — `Alt+←` / `Alt+→` で一覧の順に確認でき、閉じて開き直す必要がありません
- **一覧のキーボード操作** — `↑` `↓` で行を選び `Enter` で開く
- **行ホバーのクイック操作** — 履歴の追加・画像の追加へ直接ジャンプ

### 画像の登録

スクリーンショットを撮って、そのまま `Ctrl+V` で貼り付けられます。

| 貼り付けた場所 | 動作 |
| --- | --- |
| 資産の編集中 | その資産の画像として追加し、画像タブへ移動 |
| 一覧・ダッシュボード | その画像を持つ新規資産の下書きを開く |

ドラッグ&ドロップ、ファイル選択、画像URLの入力にも対応しています。
保存前に長辺1600px・WebP品質85%へ自動圧縮するため、大きなスクリーンショットを
そのまま貼っても IndexedDB を圧迫しません（画像の追加・削除は即時保存されます）。

### データの保存とバックアップ

画像の実体は `images` ストアに **Blob のまま** 保存し、資産レコードは参照だけを持ちます。
base64 で埋め込む方式に比べて、容量が約33%小さく、保存も速くなります。
以前のデータは起動時に自動で移行されます。

| ストア | 内容 |
| --- | --- |
| `assets` | 資産（画像は `{ id, comment, selected }` の参照のみ） |
| `tags` / `masters` | タグ階層とマスタ定義 |
| `images` | 画像の実体（Blob）、MIMEタイプ、サイズ |
| `system` | 表示設定・使用実績などのアプリ設定 |

バックアップは **ZIP形式** です。「データ管理 → ZIPでバックアップ」で書き出せます。

```
asset-manager_2026-08-18.zip
├── data.json     資産・タグ・マスタ定義・表示設定
├── images/       登録画像（元の形式のまま。解凍すればそのまま使えます）
└── README.txt    内容と戻し方の説明
```

`data.json` の `assets[].images[].file` が `images/` 内のファイル名を指しています。
復元は「バックアップから復元」から。ZIPと旧形式のJSONを自動で判別します。
ZIPの読み書きは外部ライブラリを使わず `js/zip.js` で実装しており、
一般的な解凍ソフトで作成・展開したZIPとも相互にやり取りできます。

### キーボードショートカット

アプリ内では `?` キーでいつでも一覧を表示できます。

| キー | 動作 |
| --- | --- |
| `Ctrl (⌘) + K` | 資産・タグ・操作を横断検索（コマンドパレット） |
| `/` | 表示中の一覧を絞り込む |
| `N` | 新規資産を登録 |
| `Ctrl (⌘) + V` | 画像を貼り付けて登録 |
| `Ctrl (⌘) + S` | 編集中の資産を保存 |
| `↑` `↓` / `Enter` | 一覧の行を選ぶ / 開く |
| `Alt + ←` / `Alt + →` | 資産詳細で一覧の前後へ移動 |
| `G` → `D` / `G` → `A` | ダッシュボード / 資産一覧へ移動 |
| `1` / `2` / `3` | リスト / カード / カレンダー表示 |
| `?` | ショートカット一覧 |
| `Esc` | 最前面のモーダル・パレット・メニュー・絞り込みポップオーバーを閉じる |
| `Delete` | グラフビューで選択中のノード・接続を削除 |

## 設計方針（UI/UX）

認知負荷を下げるために、次の原則で作っています。改修時もこれに沿ってください。

1. **彩度を抑えた深い色で構成する** — 明るく鮮やかな色は最初は目を引きますが、
   毎日長時間見る道具では疲れます。アクセントはスチールネイビー（`#275388`）に統一し、
   状態色も一段深いトーンで揃えて、画面全体の刺激量を下げています。
2. **色は意味を持つときだけ使う** — UIの約9割はニュートラル。彩度の高い色は
   「状態」と「次に取るべき行動」だけに割り当てます
   （緑=正常 / 琥珀=注意 / 赤=停止 / 灰=対象外 / ネイビー=操作・情報）。
3. **情報密度を優先する** — 一覧で一度に把握できる件数が多いほど、スクロールと記憶の負担が減ります。
   既定は「コンパクト」。じっくり読みたい場面のために「ゆったり」も選べます。
4. **画面の役割を混ぜない** — ヘッダー=「どこを見るか・何をするか」（ページ切替タブと主要操作）、
   フィルタバー=「今どういう状態か」（稼働状況・マスタごとの条件・件数）。この2層に別種の操作を混在させません。
5. **主役に場所を譲る** — 常時展開のサイドバーは置かず、一覧・要対応などのメイン領域を画面幅いっぱいに確保します。
   タグ階層・操作説明などのサブ情報はドロップダウンや折りたたみに畳み、必要なときだけ開きます。
6. **記憶させない** — 適用中の絞り込みは必ずフィルタバーに表示し、ショートカットは操作の近くに常時併記します。
7. **推測させない** — アイコンのみのボタンは使わず、空状態には理由と次の操作を必ず添えます。
8. **元に戻せる** — 破壊的操作は影響範囲を事前に伝えるか、「元に戻す」を用意します。

画面表示・UIを変更するときは、`CLAUDE.md` の「UI/UX 改修の進め方」（7案を実画面で比較してスコアで決める手順）に従います。
v3.0.0 の評価記録は [`docs/uiux-review.md`](docs/uiux-review.md) にあります。

## カスタマイズのポイント

- **ステータスの追加・変更** — `js/config.js` の `STATUS_DEFS` に1行追加するだけで、
  資産編集画面のチェックボックス・一覧のバッジ色と行頭ドット・フィルタバーの稼働状況・
  ダッシュボードの内訳・資産構成グラフのノード色に自動反映されます。
- **配色・余白・角丸などのデザイン** — `css/base.css` の `:root` にあるデザイントークンを変更してください。
  プリミティブ（`--p-600`、`--n-200` など）とセマンティック（`--primary`、`--danger` など）の2層構造です。
- **表示密度** — `css/base.css` の密度トークン（`--d-row-py` など）で調整できます。
  `html[data-density="cozy"]` が「ゆったり」表示の上書き定義です。
- **リストの列** — 画面上の「列」ボタンから変更できます（定義は `js/main.js` の `availableColumns`、
  既定の列は `js/config.js` の `getDefaultListColumns()`）。
- **画像の圧縮設定** — `js/image-input.js` の `IMAGE_MAX_DIMENSION` / `IMAGE_QUALITY` で調整できます。
- **データ形式のバージョン** — `js/config.js` の `DATA_FORMAT_VERSION`。
  DBスキーマとバックアップZIPの互換性判定に使われます。

## 依存関係

| ライブラリ | 提供元 | 用途 |
| --- | --- | --- |
| Dexie.js 3.2.4 | 同梱（`vendor/`） | IndexedDBによるデータ永続化 |
| Font Awesome 6.4.0 | CDN | アイコン |
| Google Fonts (Inter / Noto Sans JP) | CDN | フォント |

データの保存・読み込みはオフラインでも動作します（アイコン・フォントのみCDN依存のため、
完全オフラインで使う場合は Font Awesome も同様に `vendor/` へ同梱してください）。
